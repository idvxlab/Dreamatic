# 2026-10-10 Designer authoring incident

## Evidence and responsibility

Run `project-2026-10-10-c295768d` loaded the new runtime fingerprint and Pi 0.85.1.
It was not a stale-backend reproduction. Research completed; Designer did not
commit a design before its first invocation was interrupted by the repeated-input
failure limit. Review/build/export had not started in the inspected record.

The first Designer invocation had two rejected Skill calls: one named Skill was
bound as primary to incompatible space/industrial scopes, then several different
Skills were described in duplicate scope bindings under one name. Its first
Context call put typography and consistency fields beside system. The next three
calls put strategy/deliverables/presentation outside changes, so each entire
submission was rejected. The second invocation repeated the incompatible primary
bindings before correcting them. Research had separately made one misplaced
Context-envelope call and corrected it. Source-fetch timeout/socket/size failures
were preserved as research gaps; they are separate from these authoring errors.

The previous change was incomplete. The v2 tool description still instructed
Designer about v1 tasks/removeTasks/replaceTasks, gave a Reviewer-specific example,
and image-prompting still required unified image tasks. Passing mostly historical
v1 fixtures and one small ideal v2 example did not establish recovery for actual
model outputs. Introducing a new contract without testing the model-visible
instructions and the actual failure path was the verification mistake.

## Repair principles

- Keep one v2 authoring model and retain historical v1 compatibility. Versioned
  tool descriptions, runtime handoffs, Designer MD and image-prompting now agree.
- Keep the canonical changes envelope. Prepare only unambiguous misplaced named
  role roots into that envelope, and uniquely declared system_thesis/palette/typography
  into system, preserving every submitted value. Never infer
  domain content, pick conflicting values, accept unknown roots, downgrade the
  contract, or approve incomplete output. The same role/schema/ownership/version
  validation follows preparation. Unknown inner roots give specific placement
  guidance; small merged updates avoid regenerating entire designs after errors.
- One use_skill call loads one name; all its bindings refer to that same Skill.
  Incompatible primaries remain rejected atomically, with eligible scopes and
  matching catalog calls. Serialize activation and receipt snapshots/writes so
  parallel loading cannot overwrite newer evidence or roll back another binding.
- Diagnose HTML output kind at working readiness, before publication. HTML design
  documents use html_page; purpose expresses the document's domain meaning.
  execution.uses specifies dependency order. Only HTML dependencies on generated
  images derive image resources; page links and edit anchors do not become copied
  HTML image resources.
