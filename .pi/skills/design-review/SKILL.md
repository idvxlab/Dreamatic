# Review the decision and its evidence

Judge against the actual brief and medium. Preserve the selected concept and user
constraints unless the review identifies a concrete reason to change them. Separate
blocking requirements, substantive design weaknesses and optional refinements.

## Match claims to what can be inspected

A written proposal supports review of intent, completeness, relationships and
internal consistency. Authored source supports some structural and content checks.
Actual pixels support visual observations only when an image inspection capability
is available. Runtime behavior needs executed tests. None of these alone proves
usability, compliance, physical feasibility or production readiness.

For each claimed defect identify the available evidence and the relevant acceptance
criterion. Without actual output inspection, phrase fidelity, text legibility and
cross-view continuity as checks still needed, not observed failures or successes.
Do not introduce another model call, tool or permission solely by invoking this method.

## Evaluate the important relationships

Check brief coverage and each view's purpose before aesthetic polish. Compare
professional logic, hierarchy, recognition, coherence and necessary content across
actual variants. Distinguish productive variation from broken invariants and
intentional expression from accidental inconsistency.

For edits, compare requested changes with preservation constraints and real input
references. A style reference is not automatically the composition base. Check
size/fidelity requirements against actual metadata or inspected results; recorded
intent alone does not establish that the provider complied.

For exhibitions, check whether the argument and work arrangement communicate the
proposal and whether required work, explanations and citations remain accessible.
A source check is not a claim that a browser or assistive technology test passed.

## Prioritize a useful revision

Explain the consequence, smallest effective correction and affected views/assets.
Retain successful work. Suggest regeneration only for a demonstrated image problem,
not to compensate for weak presentation layout. State residual uncertainty and
future checks. Return the review through the host's existing output/history mechanism
rather than inventing a new report, approval gate or fixed artifact count.
