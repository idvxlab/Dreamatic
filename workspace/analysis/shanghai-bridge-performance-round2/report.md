## 下一步优化顺序

1. **优先稳定页面验收与修复流程。** 移动端溢出、目标元素不在视口、错误工具字段仍反复出现。对需要展开的导航生成真实交互步骤，对移动断点同时检查；将角色允许字段和修复路径清晰地提供给模型。文化大桥约 88 万 Token 的修复时段是可定位的优化目标。
2. **单独衡量图像等待。** 展示成功调用耗时、失败尝试耗时、body 停滞与重试，并保留已完成图片。最新项目没有失败，但成功图像调用仍使 Builder 达到 7.72 分钟。
3. **区分总 Token 与未缓存输入。** 本轮缓存占比提高，但请求次数从平均 52.75 增至 62；缓存命中不能替代减少无效往返。
4. **固定测试规模后复测。** 三个新增项目 codeFingerprint 分别为 406a9f8f76、70adf1dbcf、1b0225f9e4；模型均 qwen3.7-plus、图像模型均 gpt-image-2、configuredThinkingLevel 均 off。版本及需求不同，仅 3 次运行不能证明某项代码改动带来的因果提升。建议固定 7 图 + HTML、相同尺寸/交互和 brief，在同一版本重复测试，比较阶段中位数、尾部耗时、修复率与缓存外输入。

## 统计口径与核验

- 总历时：run-state.createdAt 至 updatedAt（export_done）。流程历时：design_categories_identified 至 export_done。
- 按 requestId 去重汇总 provider_response_complete.usage，不再叠加阶段或 session 的重复用量。本轮 186/186 请求有完成记录，四个专业角色的会话 Token 与请求日志一致。累计 11 个项目为 608/608 请求有完成记录。
- totalTokens = input + cacheRead + cacheWrite + output；cacheWrite 为 0。reasoning 已计入 output，不重复叠加。
- 图片 Token、真实费用、CPU/内存、同时间外部服务负载未记录。图像请求部分并行，不能把各次调用耗时相加当作总历时。
- 完成率只针对已找到的这些项目，不代表所有系统请求的总体成功率。
