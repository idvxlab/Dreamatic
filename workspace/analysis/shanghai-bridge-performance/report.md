# 上海长江大桥设计项目运行性能对比

分析日期：2026-10-11（Asia/Shanghai）。样本为 workspace/runs 中 8 个上海长江桥梁设计项目。全部为 full 工作流、设计契约 v2，文本模型均为 qwen3.7-plus；研究预算均为 8 次查询、10 次抓取。

## 统计口径

- 总历时：run-state.createdAt 至 updatedAt（export_done）；包括前期澄清、等待、重试。流程历时：design_categories_identified 至 export_done，便于排除前期不同长度的间隔。两者均非 CPU 执行时间。
- 文本 Token：仅汇总 .performance/model-requests.jsonl 中按 requestId 去重的 provider_response_complete.usage；不再叠加会话文件或阶段 metrics。所有 422 个请求均有响应完成记录；四个专业角色的 Token 与对应会话文件逐项一致。
- totalTokens = input + cacheRead + cacheWrite + output；本样本 cacheWrite 为 0。input 是日志中未缓存输入部分。reasoning 单独列示，已包含在 output 中，不重复叠加。
- 图像调用次数包含失败与重试；图片 Token 与真实账单未记录。费用字段均为 0，不代表真实费用为零。
- 交付数量按 artifact-manifest.artifacts 中的设计成果统计，页面附属文件与导出副本不重复计数。

## 主要结论

1. **常规运行约 20–28 分钟，存在明显长尾。** 总历时平均 27.78 分钟、中位数 23.66 分钟，范围 20.21–51.31 分钟。流程历时平均 25.21 分钟、中位数 21.97 分钟。生态大桥总历时 31.67 分钟，但流程仅 22.92 分钟；前期 8.75 分钟间隔不能归因于模型慢。
2. **Designer 是文本消耗与常规耗时的主要来源。** 累计 8,888,725 Token，占总量 52.9%；Researcher 17.4%、Reviewer 14.2%、Orchestrator 12.1%、Builder 3.4%。Designer 单次约 6.04–13.68 分钟，多数项目是最长阶段。
3. **Token 大部分来自重复输入上下文。** 累计 16,799,348 Token = 4,549,251 未缓存输入 + 11,782,528 缓存读取 + 467,569 输出。输入侧缓存占比约 72.1%；输出仅占总量 2.8%。每项目平均 2,099,919 Token；每次文本请求平均约 39,809 Token。应同时展示总 Token、未缓存输入和缓存读取，避免混淆吞吐量与费用。
4. **最慢项目并非 Token 最多。** cc1a21e4 用 1,806,508 Token，却耗时 51.31 分钟；Builder 33.71 分钟，占总历时约 65.7%。5 张图产生 8 次图像请求、3 次响应 body 停滞重试。异常尝试分别持续约 241.5、432.0、976.8 秒，期间触发“60 秒无数据”规则；成功尝试也有 4–8 分钟的长等待。由日志可定位到图像响应链路，但不能进一步确定供应商计算、代理或网络哪一环负责。
5. **页面和工具契约修复反复出现。** e62616cb 的 Designer 26 次文本请求、1,836,305 Token，约占该项目 67.9%；日志包含 Skill 范围不匹配、字段类型错误、未声明图片资源、移动端导航点击超时。生态大桥 22 次 Designer 请求、1,454,439 Token，两次导航预检失败；其生成图像调用耗时主要为几十秒到两分钟，并非 31.67 分钟总历时的主要解释。
6. **可选性能参照应匹配交付规模。** 2b32009b 用 1,654,126 Token、22.03 分钟完成 7 图 + HTML，是样本中总 Token 最低的项目；14b9d7e5 用 1,733,693 Token、20.21 分钟完成 5 图 + HTML，是总历时最短项目。cc1a21e4 同样 5 图 + HTML，却慢约 2.54 倍，差异主要集中在构建阶段。
7. **完成率与质量不是同一指标。** 8/8 项目记录为 complete，文件完整性与交互检查均 passed；全部仍为 visualFidelity=not_assessed、engineeringFeasibility=not_validated、userAcceptance=pending。这里只能确认流程完成和交付检查通过，不能推断设计质量或工程可实施性相同。

## 优化优先级

- **P0：图像链路的长尾可观测性与恢复。** 独立监控请求头、响应 body、停滞、失败尝试耗时和队列；对已成功图像保留结果，仅重试失败项。结合真实响应采样评估代理和供应商链路，再调整 idle/deadline 策略，不能仅通过缩短超时保证更快。
- **P1：减少 Designer 修复与大上下文重复传输。** 为移动导航检查生成正确的展开步骤和唯一选择器；提前校验工具参数与资源声明；按阶段只提供必要的研究结论、设计约束与指定文件片段。分别衡量正常设计与修复的请求数、Token 和耗时。
- **P1：统一看板口径。** 同时显示前期澄清历时、流程历时、各阶段墙钟时间、文本模型等待、图像调用/重试、缓存与未缓存输入、交付规模、质量状态。当前 completion-summary 的流程时间与项目 createdAt 口径不同，生态项目相差约 8.75 分钟。
- **P2：做受控复测。** 固定 brief、图像数量/尺寸、页面交互要求、运行版本和供应商；重复运行后比较中位数及尾部耗时，再判断代码变更是否提升性能。本次样本有多个 codeFingerprint，且 eea464ab 同一项目出现两个指纹，不能将按时间排列的表现变化直接归因于版本改进。
